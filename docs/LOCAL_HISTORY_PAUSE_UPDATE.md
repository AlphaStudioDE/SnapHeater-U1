# Pause, local history, usage counters and Android tools

Local implementation update, 2026-09-06. No publication or hardware flashing
is implied by this document.

## User-visible behavior

- Legacy Smart Resume and its recovery-window marker were subsequently removed
  at the user's request. This does not remove the explicit heating pause/resume
  button or the separate printer pause-hold policy.

- Pause heating is above Stop. It retains the current task but stops heat.
  Normal cooling and fault supervision continue. Resume is explicit.
  Heat Soak and task clocks do not advance during pause. The global maximum
  heating-session limit is deliberately not extended.
- History is between Modes and Settings. Only live, valid measurements are
  saved on this phone, at most every 10 seconds. The chart offers 2 h / 24 h;
  The history database is excluded from Android automatic cloud/device backups.
  CSV streams all saved samples for the selected full device identity.
  Missing intervals, sequence gaps and boot boundaries are not joined.
  Panda catch-up now retains decimal temperatures, deduplicates by boot/sequence
  and preserves invalid readings as null. See [protocol](HISTORY_SYNC.md).
- The diagnostic JSON export uses an explicit whitelist. It is a current
  diagnostic snapshot, not a complete historical incident archive. It excludes
  passwords, REST tokens, Wi-Fi configuration and network addresses.
- OTA is separate from history: select a trusted application .bin while
  connected by authenticated LAN. The client checks full device identity,
  image header and inactive slot capacity; firmware remains authoritative for
  maintenance admission and image validation. The returned digest is compared.
  A timeout may follow an accepted update: reconnect and inspect the actual
  running version before retrying. There is no unattended retry.
- Runtime counters belong to Panda NVS. Heater time and filter/fan time are
  software output-runtime estimates, not measured mains conduction or filter
  condition. A daily summary appears after connection when counters are valid.

## Memory, persistence and notification boundaries

The Panda ring buffer uses 720 records of 16 bytes: 11,520 bytes of internal
RAM, not PSRAM. Task stack and metadata are additional. Sampling interval is
10 seconds. The buffer is volatile and overwrites its oldest record. Android
catch-up is connected over BLE and REST in the subsequent history-sync change.

Usage counters are loaded once and added to the current boot runtime. NVS is
written only after acquiring maintenance under the control policy guard.
The policy guard is released during flash I/O, but maintenance remains active,
so no control channel can start heating during the write. Existing strict
maintenance rules require stopped outputs and sensors below 30 C.
Only changed totals are written. Flash errors do not stop thermal control;
they mark counter availability false. A power cut before a checkpoint can
lose all uncheckpointed runtime since the preceding checkpoint.

Notifications use the last 32 firmware events in RAM. The BLE read-only UUID
is 7b2f1005-4a6f-4c2d-9a1e-2f4f53485531; REST includes the same compact envelope
under notifications in /api/events. Fields are device_id, boot, events;
each event has seq, level, code. Free-form log messages are not in this envelope.
Android posts warnings/errors/critical events and cycle/report completion
events, then saves a per-device boot+sequence receipt. That receipt acknowledges
local notification submission, not delivery to a person or a firmware fault.
No notification dismissal clears a hardware fault or resumes heating.

The optional connected-device foreground service has a visible persistent
notification and Stop action. It watches one explicitly selected Panda and
does not auto-discover another device. It never acquires a control lease or
sends heater commands. In foreground, the UI reads events; in background the
service reads them. GATT sessions are serialized per device, and a command can
cancel an advisory-event read. Permission denial, channel disablement, process
death, radio loss, queue overwrite and reboot still prevent guaranteed delivery.

## Verification scope

Before history-sync: 62 Python tests, 3 Kotlin tests, real-mutex safety host test,
Android APK and ESP-IDF tester build passed. Android lint: zero errors;
127 warnings remain (not a claim of a warning-free application).

Run Android testDebugUnitTest before the Python suite, because the integration
tests consume command fixtures generated by Kotlin. The suite covers actual
production parser helpers, pause/OFF/fault control scenarios, ring overwrite
and byte budget, bounded event serialization without free-form messages, and
event receipt deduplication across reboot. It does not simulate Android SQLite
storage, real BLE transfers, power interruption during NVS, device OTA or mains
waveforms. Those require integration/hardware checks.

Symbiont ventilation control and automatic printer rediscovery remain deferred.
Subsequent work added acquisition freshness and passive dual-raw-invariance
detection. See [sensor diagnostics](SENSOR_DIAGNOSTICS.md); plausible sensor
failures are still not universally detectable.
